## setuid capability 提权

尝试使用该凭证登录ssh，成功登录，只能看到极少进程信息（原因见下文）

![](/images/htb-cap/5.png)

在linux一般需要root权限才能抓取流量，回顾web入口处服务提供了5秒内流量抓取下载功能，发现web在常见的 /var/www/html 目录下，使用的 flask 框架，并且开启了debug模式

![](/images/htb-cap/6.png)

关键：在 capture 函数中，使用python调用 `os.setuid(0)` 提升权限为 root，python具有setuid的能力

```python
@app.route("/capture")
@limiter.limit("10 per minute")
def capture():

        get_lock()
        pcapid = get_appid()
        increment_appid()
        release_lock()

        path = os.path.join(app.root_path, "upload", str(pcapid) + ".pcap")
        ip = request.remote_addr
        # permissions issues with gunicorn and threads. hacky solution for now.
        #os.setuid(0)
        #command = f"timeout 5 tcpdump -w {path} -i any host {ip}"
        command = f"""python3 -c 'import os; os.setuid(0); os.system("timeout 5 tcpdump -w {path} -i any host {ip}")'"""
        os.system(command)
        #os.setuid(1000)

        return redirect("/data/" + str(pcapid))
```

验证，提权

```bash
nathan@cap:~$ python3
```

## 隐藏进程原因

查看 `/proc` 目录的挂载选项，可以看到 `/proc` 目录是以 `hidepid=2` 挂载的，普通用户无法查看其他用户的进程信息

hidepid 选项说明：

hidepid=0：所有人都能看到所有进程（默认）

hidepid=1：用户只能看到自己的进程，但能看到其他用户的 /proc/<pid>/ 目录

hidepid=2：用户只能看到自己的进程，完全看不到其他用户的进程信息

```bash
root@cap:~# mount | grep proc
proc on /proc type proc (rw,relatime,hidepid=2)
systemd-1 on /proc/sys/fs/binfmt_misc type autofs (rw,relatime,fd=28,pgrp=1,timeout=0,minproto=5,maxproto=5,direct,pipe_ino=26439)
binfmt_misc on /proc/sys/fs/binfmt_misc type binfmt_misc (rw,nosuid,nodev,noexec,relatime)
```
