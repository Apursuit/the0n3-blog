## 项目概览

这是一个基于 PHP 的静态博客生成器。它读取带 YAML Front Matter 的 Markdown 文章与独立页面，转换为 HTML，并生成首页、文章页、标签页、分类页、归档页以及分类/标签各自的落地页。构建结果输出到 dist/ 目录，可直接部署到任意静态服务器。

核心特点：

- 文章源为 Markdown，支持 Front Matter
- 生成首页、文章页、独立页面、标签页、分类页、归档页
- 分类与标签拥有独立落地页，便于检索与收录
- 主题切换、代码高亮、目录、阅读进度、图片增强、全文搜索等前端能力
- 构建过程有日志输出

## 运行方式


生成新文章模板：

```bash
php main.php new "文章标题"
```


本地构建静态站点：

```bash
php main.php build
```

构建后，dist/ 目录下会生成所有静态文件，在 dist 目录下开启 web 服务，访问 http://localhost:8000 进行预览：

```bash
php -S localhost:8000 -t dist/
```

## 目录结构

```plaintext
.
├── assets/      # 前端资源（CSS / JS / Prism 代码高亮）
├── config/      # 站点配置目录
├── logs/        # 构建日志目录（默认追加写入，超过14天自动清空重写）
├── posts/       # Markdown 文章源文件（支持子目录嵌套）
├── pages/       # 独立页面源文件（关于、友链等，不进入文章列表）
├── public/      # 静态资源（构建时会原样拷贝至 dist/ 根目录）
├── images/      # 图片资源（构建时会原样拷贝至 dist/images/）
├── src/         # 核心 PHP 业务逻辑代码
├── templates/   # HTML 页面模板
├── dist/        # 构建后的最终静态站点输出目录（执行 build 后生成）
└── main.php     # CLI 工具统一入口文件
```

## 文章格式

每篇文章为 Markdown 文件，需包含 YAML Front Matter，例如：

```yaml
---
title: Hello World
date: 2026-03-20
permalink: /posts/hello-world/
tags:
    - 示例
categories:
    - 示例
pin: 0
draft: false
sidebar: true
---
```

文章文件放在 posts/ 下即可（可分子目录）。

## 构建流程

入口：main.php

1) 初始化配置
2) 创建 Generator 实例
3) 执行 Generator::run()

Generator::run() 的八个步骤：

1) 清理输出目录
    - 删除并重建 dist/
2) 复制静态资源
    - assets/ 复制到 dist/assets/
    - public/ 复制到 dist/
    - images/ 复制到 dist/images/
3) 加载文章
    - 读取 posts/ 下的 Markdown
    - 解析 Front Matter
    - 过滤 draft: true 的文章
4) 加载独立页面
    - 读取 pages/ 下的 Markdown
    - 目录不存在时返回空数组，不阻断构建
5) 校验文章
    - 校验必填字段与类型
    - 校验 permalink 合法性与冲突
6) 处理文章数据
    - Markdown 转 HTML
    - 按日期排序
    - 聚合 tags/categories/archives
    - 分类与标签按文章数降序排列
7) 生成站点页面
    - 生成文章页、独立页面
    - 生成首页分页
    - 生成标签页、分类页、归档页及其落地页、404
    - 生成 sitemap.xml（依赖 config/site.php 的 url）
8) 生成搜索索引
    - 输出 dist/search-index.json

说明：

- 步骤 7 之前会调用 GitLastmod::init()，sitemap 的 lastmod 取自 git 提交历史，读取失败会中断构建。
- 如果 config/site.php 的 url 未配置或为空，会跳过 sitemap 生成并输出 warning 日志。


### Front Matter 字段说明

必需字段（缺失会报错）：

- title：文章标题
- date：日期（支持 YYYY-MM-DD 或可被解析的字符串）
- permalink：文章永久链接（例如 /posts/hello-world/）

可选字段（未填写会自动补默认值）：

- tags：标签数组，默认 []
- categories：分类数组，默认 []（支持单个字符串）
- pin：置顶优先级，0-3，数字越小优先级越高，默认 0
- draft：是否草稿，默认 false（true 时构建会跳过）
- sidebar：是否显示文章目录侧边栏，默认 true


示例：
	
```txt
---
title: Hello World
date: 2026-03-20 12:00:00
permalink: /posts/hello-world/
tags:
	- 示例
categories:
	- 笔记
pin: 1
draft: false
sidebar: true
---
```

## 图片加载策略

构建时会对 Markdown 与页面 HTML 中的图片做统一后处理：

- 所有图片都会补充 `decoding="async"`，减少图片解码对页面渲染的阻塞。
- 每篇文章或独立页面中的第一张图片不会自动补充 `loading="lazy"`，避免首屏图片或 LCP 图片被延后加载。
- 从第二张图片开始，如果没有手动声明 `loading`，会自动补充 `loading="lazy"`，降低长文章中大量截图的首屏加载压力。
- 如果图片已经手动写了 `loading` 或 `decoding`，构建器会保留原值，不会覆盖。
- 图片点击放大由 `assets/features/image-enhance/` 提供；给图片添加 `data-no-lightbox="true"` 可以跳过灯箱，例如友链头像。

示例：

```html
<img src="/images/example/cover.png" alt="cover" decoding="async">
<img src="/images/example/step-1.png" alt="step 1" decoding="async" loading="lazy">
<img src="/images/friends/logo.png" alt="friend avatar" data-no-lightbox="true" loading="lazy" decoding="async">
```

## 备注

- 主题与排版变量在 assets/css/site.css 中
- 目录由前端脚本根据 h2/h3 生成
- 阅读进度条：assets/features/reading-progress/script.js + assets/features/reading-progress/style.css
- 图片增强：assets/features/image-enhance/script.js + assets/features/image-enhance/style.css
- 导航栏自动显示：assets/js/navReveal.js + assets/css/nav-reveal.css
- Callout 与图片加载属性由 Markdown 后处理完成（src/Markdown.php）
- 构建日志写入 logs/build.log（默认追加写入；超过 14 天会自动清空重写；每次构建会写入分隔线）
- main.php 固定时区为 Asia/Shanghai，保证日志与日期输出为北京时间
- permalink 会做冲突校验：不能与系统页（/tags/、/categories/、/archives/）或 public/images 下已有文件路径冲突

## 分类与标签逻辑

- tags: 每篇文章可多个，聚合为标签页数据
- categories: 每篇文章可多个，聚合为分类页数据
- 分类与标签各自生成独立落地页：/categories/{名称}/、/tags/{名称}/
- 索引页展示下辖文章列表，点击条目进入对应的独立落地页

## 置顶逻辑

- pin > 0 表示置顶，1 优先级最高
- 置顶文章最多 3 篇
- 首页分页仅第一页显示置顶文章
- 置顶文章按 pin 升序、日期降序排序

## 分页逻辑

- 首页分页大小为 10 篇
- /index.html 为第一页
- /page/{n}/index.html 为后续分页
- 分页导航为上一页 / 当前页 / 下一页

## Sitemap

构建时会在 dist/ 下生成 sitemap.xml，用于 SEO。

- 域名来源：config/site.php 的 url（会自动去掉末尾的 /）
- 输出位置：dist/sitemap.xml
- 收录的页面：
    - 首页：/
    - 独立页面：pages/ 下各页面的 permalink
    - 全部文章 permalink（Front Matter 的 permalink）
- 不收录：分页 /page/{n}/、标签与分类索引页、标签与分类落地页、归档页
- lastmod 规则：
    - 文章与独立页面：取自 git 提交历史中该文件的最后一次提交时间
    - 首页：全站文章 lastmod 的最大值
    - 未提交的新文件：退回 Front Matter 的 date
- 依赖：读取 git 历史失败时会中断构建，避免产出 lastmod 全部失效的 sitemap

## 模板结构

- templates/layout.php
    - 基础布局，包含导航、主题切换、脚本样式引入
- templates/index.php
    - 首页文章列表 + 分页
- templates/post.php
    - 文章页，支持目录、元信息与评论区容器
- templates/page.php
    - 独立页面模板（关于、友链等）
- templates/tags.php / templates/categories.php
    - 标签 / 分类索引页
- templates/taxonomy.php
    - 单个分类或标签的落地页
- templates/archive.php
    - 归档页
- templates/404.php
    - 404 页面

## 前端能力

- assets/js/site.js
    - 返回顶部 + 文章页目录生成与滚动定位
- assets/js/navReveal.js
    - 滚动时导航栏显隐
- assets/js/ThemeSwitch.js
    - 主题切换
- assets/features/reading-progress/
    - 阅读进度条
- assets/features/image-enhance/
    - 图片点击放大
- assets/features/code-fold/
    - 代码块折叠
- assets/features/giscus-theme/
    - 按访客当前主题注入 giscus，并在切换主题时同步
- assets/features/nav-menu/
    - 移动端导航菜单样式

features 目录下的子目录由 layout.php 自动扫描引入，新增功能只要放进该目录即可。

样式入口：assets/css/site.css

## 博客样式自定义

博客文章由 markdown 转 html 后，样式大多数由 /assets/css/github-markdown.css 直接提供，部分博客样式在 /assets/css/site.css 中定义，site.css导入顺序位于 /assets/css/github-markdown.css 之后，因此，可以在 site.css 中覆盖或自定义样式来调整博客的外观。

## 静态资源映射

- assets/ -> dist/assets/
- public/ -> dist/
- images/ -> dist/images/

文章中推荐使用绝对路径：

- /images/xxx/1.png

## 日志

- 构建日志写入 logs/build.log
- 控制台输出带时间戳与中文等级

补充：

- 日志默认追加写入，并在每次构建开始写入分隔线（便于区分多次构建）。
- 默认保留 14 天：当 build.log 文件超过 14 天未更新，会自动清空重写。
- 入口 main.php 固定时区为 Asia/Shanghai，保证日志与日期输出为北京时间。

## permalink 冲突校验

构建时会校验文章 permalink 不与以下路径冲突：

- 系统页：/tags/、/categories/、/archives/
- public/ 下的静态文件路径（会被视为站点根路径下的真实文件）
- images/ 下的静态文件路径（会被视为 /images/... 的真实文件）
